# PLAN: AIU Chat — веб-чат студентов Международного университета Астаны

Статус: **ЧЕРНОВИК, ждёт «ок» пользователя.** Код не пишется до подтверждения.

## 1. Цель
Бесплатный realtime-чат для студентов разных курсов: вопросы по предметам и экзаменам, общение со старшекурсниками. Публичная ссылка вида `*.vercel.app` для демонстрации преподавателю и студентам.

## 2. Стек (подтверждён)
| Слой | Выбор | Зачем |
|---|---|---|
| Frontend | React + TypeScript + Vite | Быстро, бесплатно на Vercel |
| Стили | Tailwind CSS | Адаптивность десктоп/телефон |
| Backend | **Supabase** (без Java/Spring) | Auth, Postgres, Realtime, Storage, RLS в одном |
| Вход | Google OAuth + e-mail/пароль (Supabase Auth) | По ответу: Google или e-mail |
| Realtime | Supabase Realtime (postgres changes) | Сообщения без перезагрузки |
| Файлы | Supabase Storage | Фото, видео (≤ 50 МБ), голосовые |
| Хостинг | Vercel (free) | Ссылка без домена |
| Уведомления UI | Sonner (toast) | Уже есть скилл |

Почему не Spring: Vercel не запускает Java; отдельный хостинг = сложнее и «засыпает» на бесплатном тарифе. Spring можно добавить позже, если понадобится логика вне Supabase.

## 3. Функции MVP
1. Регистрация и вход: Google, e-mail+пароль; выход; доступ любому (ограничение по домену — позже).
2. Профиль: имя, курс (1–4+), специальность, аватар.
3. Главный экран: список моих чатов + поиск групп.
4. Группы-предметы: создание, публичный поиск, вступление/выход, ссылка-приглашение.
5. Роли в группе: админ (создатель) / участник; админ удаляет чужие сообщения и участников.
6. Личные сообщения 1-на-1.
7. Чат realtime: текст, ссылки (кликабельные), фото, видео (≤ 50 МБ), голосовые.
8. Ответ на сообщение и реакции (эмодзи).
9. Адаптивный UI (десктоп: список+чат рядом; телефон: экраны по очереди).

Вне MVP: оплата, мобильное приложение, звонки, push-уведомления, e-mail домен вуза, статус «печатает».

## 4. Модель данных (Postgres, черновик)
- `profiles` (id = auth.users.id, display_name, avatar_url, course, major, created_at)
- `chats` (id, type `group|direct`, name, description, is_public, invite_code, created_by, created_at)
- `chat_members` (chat_id, user_id, role `admin|member`, joined_at) — PK (chat_id, user_id)
- `messages` (id, chat_id, sender_id, body, reply_to, created_at, deleted_at)
- `attachments` (id, message_id, kind `image|video|audio`, storage_path, size, duration)
- `reactions` (message_id, user_id, emoji) — PK по всем трём
- Storage bucket `chat-media` (приватный, доступ по членству в чате).
- RLS на всех таблицах: читать/писать сообщения может только участник чата; группы с `is_public` видны в поиске; удалять чужое — только admin.

## 6. Этапы (каждый — маленькие задачи через `coder`)
- **Этап 0. Основа**: создать проект Supabase и Vercel (делает пользователь), каркас `web/`, `.env.example`, подключение клиента.
- **Этап 1. Вход**: страница входа, Google + e-mail, защищённые маршруты, профиль.
- **Этап 2. Схема БД**: миграции таблиц + RLS, проверка политик.
- **Этап 3. Группы**: создание, поиск, вступление, ссылка-приглашение, роли.
- **Этап 4. Текстовый чат**: список чатов, отправка/получение realtime, ответы, реакции, личные сообщения.
- **Этап 5. Медиа**: фото, видео, голосовые, лимит 50 МБ, превью.
- **Этап 6. Адаптив и полировка**: мобильная раскладка, пустые/длинные состояния (скилл `break-ui`), анимации (скиллы Emil).
- **Этап 7. Деплой**: Vercel, переменные окружения, redirect URL для Google OAuth, проверка с двух устройств.

## 7. Что нужно от пользователя (не от кода)
- Создать бесплатные аккаунты: Supabase, Vercel (GitHub-вход).
- Для Google-входа: проект в Google Cloud Console, OAuth Client ID (подскажу по шагам на этапе 1).
- Ключи **не** отправлять в чат и не коммитить: вносятся в Vercel/Supabase и локальный `.env`.

## 8. Риски бесплатных тарифов
- Supabase free: проект **ставится на паузу после ~7 дней неактивности** → перед показом открыть его и проверить.
- Хранилище 1 ГБ, файл ≤ 50 МБ, ограничение числа одновременных realtime-соединений (хватит для класса).
- Публичный доступ «любому с Google/e-mail» значит, что зайти может кто угодно; для показа ок, дальше добавим ограничение по домену вуза.
