# PLAN: AIU Chat

Веб-мессенджер для студентов Международного университета Астаны (AIU).

Статус: **утверждён.** Этапы 0–6 выполнены, следующий — этап 7 (полировка), затем 8 (демо).

---

## 1. Цель и рамки

**Задача продукта.** Студенты разных курсов задают вопросы по предметам и экзаменам и получают ответы, в том числе от старшекурсников. Общение идёт в публичных группах по предметам и в личных сообщениях.

**Цель первой версии.** Рабочее демо по публичной ссылке `aiu-chat.vercel.app` (или похожей). Его можно открыть с компьютера и с телефона и переписываться в реальном времени, например на показе преподавателю.

**Ограничения.**
- Бюджет 0 ₸: нет своего домена, только бесплатные тарифы.
- Мобильного приложения нет, но веб-версия должна быть удобной на телефоне.
- Оплаты нет.

## 2. Готовые решения: что берём, что нет

| Вариант | Решение | Почему |

Доделывать чужой учебный код дольше, чем собрать на нормальном фундаменте. |
| [Supabase UI Library](https://supabase.com/blog/supabase-ui-library) (shadcn-блоки: вход, загрузка файлов, realtime-чат) | **Берём блоки входа и загрузки файлов** как основу | Официальные и совместимы с shadcn. ## 4. Архитектура

```
 Браузер (React SPA на Vercel)
   │  supabase-js (публичный ключ, права режутся RLS)
   ├── Auth ─────────── Google OAuth, e-mail + пароль
   ├── Postgres ─────── таблицы + RLS + RPC-функции
   ├── Realtime ─────── broadcast-канал на каждый чат: chat:<id>
   │                    (RPC send_message / toggle_reaction / delete_message → realtime.send)
   └── Storage ──────── приватный bucket chat-media, ссылки с подписью
```

**Ключевые решения.**

1. **Своего бэкенда нет.** Безопасность обеспечивают RLS-политики в Postgres. Операции из нескольких шагов делаются через RPC (`security definer`), например вступление по ссылке или создание личного чата.
2. **Realtime через Broadcast из БД.** Это рекомендованный Supabase способ вместо `postgres_changes`: он лучше масштабируется. Событие в приватный канал `chat:<id>` шлют сами RPC-функции, поэтому сообщение приходит сразу вместе с вложениями и автором. Подробности — в `docs/DB.md`. Подписаться могут только участники чата (RLS на `realtime.messages`).
3. **Сообщения хранятся в БД.** Realtime только доставляет их. После переподключения клиент догружает пропущенное по `created_at`.
4. **Оптимистичная отправка.** Клиент сам генерирует UUID сообщения и сразу его показывает. Если та же запись приходит из realtime, дубль не появляется.
5. **Пагинация по курсору.** Порциями по 50 сообщений, старые подгружаются при прокрутке вверх.
6. **Медиа.**
   - Путь файла: `chat-media/<chat_id>/<message_id>/<file>`.
   - Доступ к файлам через RLS Storage по членству в чате.
   - Фото сжимаются в браузере перед загрузкой.
   - Лимит 50 МБ на файл задаётся настройкой bucket.
7. **Голосовые.** Запись через `MediaRecorder`: в Chrome и Android формат webm/opus, в Safari и iOS mp4/aac. Длительность и форма волны считаются на клиенте.

## 5. Модель данных (Postgres)

```
profiles      id (=auth.users.id) PK, username UNIQUE, display_name, avatar_url,
              course smallint (1..4 | null), major text, locale (kk|ru|en),
              created_at

chats         id PK, type (group|direct), name, description, avatar_url,
              is_public bool, invite_code UNIQUE, created_by, created_at,
              last_message_at                       -- для сортировки списка

chat_members  chat_id, user_id  PK(chat_id,user_id),
              role (admin|member), joined_at, last_read_at   -- непрочитанные

messages      id uuid PK (генерирует клиент), chat_id, sender_id, body (≤ 4000),
              reply_to → messages.id, created_at, deleted_at (мягкое удаление)

attachments   id PK, message_id, kind (image|video|audio|file),
              storage_path, mime, size_bytes, width, height, duration_ms

reactions     message_id, user_id, emoji  PK(все три)

direct_pairs  user_a, user_b (a<b) PK, chat_id   -- один личный чат на пару
```

**RLS (кратко).**
- `profiles`: читать может любой вошедший, менять только свой.
- `chats`: видны публичные группы и чаты, где ты участник. Менять может только admin.
- `chat_members`: вступить можно в публичную группу или через RPC по коду. Удалить другого может admin.
- `messages`, `attachments`, `reactions`: читать и писать может только участник. Удалить своё может автор, чужое в группе — admin.

**RPC-функции.**
- `join_chat_by_code(code)`
- `get_or_create_direct_chat(other_user_id)`
- `mark_read(chat_id)`
- `search_public_groups(q)` — использует `pg_trgm`.

## 6. Функции MVP

1. **Вход.**
   - Google или e-mail + пароль, восстановление пароля.
   - После первого входа — заполнение профиля: имя, @username, курс, специальность.
2. **Главный экран.**
   - Список чатов: последнее сообщение, время, счётчик непрочитанных.
   - Поиск по своим чатам и по публичным группам.
3. **Группы-предметы.**
   - Создание: название, описание, аватар.
   - Публичный поиск, кнопка «Вступить», выход из группы.
   - Ссылка-приглашение `/join/<code>`.
4. **Роли.**
   - Создатель группы — admin.
   - Admin удаляет сообщения и участников, назначает других admin.
5. **Личные сообщения.** Написать любому пользователю: из профиля в группе или через поиск по @username.
6. **Сообщения.**
   - Текст с кликабельными ссылками.
   - Фото, видео до 50 МБ, голосовые.
   - Ответ на сообщение, эмодзи-реакции, удаление своего сообщения.
7. **Профиль и настройки.** Аватар, курс, специальность, язык (kk/ru/en), тема (системная/светлая/тёмная).
8. **Адаптивность.**
   - Десктоп: список и чат рядом.
   - Телефон: экраны по очереди с анимированным переходом, безопасные отступы под вырез экрана, поле ввода без зума.

9. **Ощущение приложения** (решение этапа 3).
   - На телефоне назад к списку — системным жестом браузера (свайп от края в Safari / жест «назад» Android) или кнопкой в шапке. Собственный свайп от края — только в установленном приложении (standalone), иначе он конфликтует с жестом браузера. Анимации «перелёта» аватара нет (убрана по решению пользователя).
   - Свайп сообщения вправо — ответ на него (этап 5).
   - Индикатор «печатает…» через Realtime (без записи в БД, этап 5). Демо-автоответ из прототипа в приложение не переносится.

**Не входит в MVP (позже):**
- редактирование сообщений, статус «онлайн»;
- push-уведомления, звонки;
- поиск по тексту сообщений;
- ограничение входа доменом вуза;
- PWA-установка (если не решим иначе).

## 7. Дизайн

- **Стиль.** Современный, «как Telegram»: пузыри сообщений, хвостики, группировка подряд идущих сообщений одного автора, разделители дат.
- **Темы.** Светлая и тёмная на CSS-токенах. По умолчанию — системная.
- **Анимации** (по правилам скиллов Emil Kowalski):
  - появление сообщения: `ease-out` до 250 мс, только `transform` и `opacity`;
  - переход «список → чат» на телефоне — сдвиг;
  - реакции и меню сообщения — pop-in;
  - всё отключается при `prefers-reduced-motion`.
- **Проверки.** Перед реализацией экранов делаем 2–3 варианта ключевых экранов через скилл `prototype` и выбираем. После реализации — `break-ui` (длинные имена, пустые списки, казахские символы) и `mobile-native`.

## 8. Языки (i18n)

- Все строки интерфейса лежат в `web/src/locales/{kk,ru,en}.json`, в коде нет текста.
- Язык определяется по браузеру. Выбор пользователя сохраняется в `profiles.locale`.
- Даты и время форматируются через `Intl`.
- Пользовательский контент (сообщения, названия групп) не переводится.
- Переводы для kk и en черновые — их надо будет проверить носителю.

## 11. Риски бесплатных тарифов

Цифры из сторонних обзоров ([пример](https://automationatlas.io/answers/supabase-free-tier-limits-2026/)). Перед этапом 1 сверим с supabase.com/pricing.

- **Пауза Supabase.** Проект засыпает после 7 дней без активности. За день до показа его нужно открыть и при необходимости нажать Restore.
- **Объёмы.** Хранилище около 1 ГБ, база 500 МБ, 200 одновременных realtime-подключений. Для класса хватит.
- **Открытый доступ.** Войти может любой с Google или e-mail. Модерация — только у admin групп.
- **Ключи.** Публичный ключ Supabase в браузере — это нормально. Секретный `service_role` ключ никогда не попадает в код и в чат.

## 12. Принятые решения

- Название: **AIU Chat**.
- Языки: kk / ru / en с переключателем. По умолчанию **русский**, если браузер не подсказал другой из трёх.
- Курсы: **метка курса в профиле**, отдельных групп по курсам нет. Все группы открыты всем, курс автора виден рядом с именем.
- Создавать группы может **любой студент**.
- Личные сообщения: **любому пользователю** по @username.
- Вход открыт любому с Google или e-mail. Ограничение доменом вуза — позже.
- Видео не больше 50 МБ.
- Стек: React + Supabase, без Java.
- Подтверждение e-mail при регистрации **выключено**: бесплатная почта Supabase не доставляет письма студентам. Поэтому восстановления пароля по почте в MVP нет; при проблемах студенту предлагается вход через Google.
- Вход через Google настраивается на этапе 2 (`docs/SETUP_GOOGLE.md`).
- Курс в профиле: 1–4 курс бакалавриата и 1–2 курс магистратуры. В БД `course`: 1–4 = бакалавриат, 5 = магистратура 1, 6 = магистратура 2.
- Специальность — свободный текст.
- Дизайн (этап 3): вариант **«Стекло»**. Тёмная тема — как в прототипе. Светлая — по мотивам фирменных цветов aiu.kz, спокойнее и контрастнее.
- Из варианта «Живой» берём жесты: свайп-ответ, свайп от края назад, «печатает…». «Перелёт» аватара убран по решению пользователя.
- Движущийся фон — только на десктопе.
- Аватар группы при создании — цвет и буквы; фото — на этапе 6.
- `/join/<code>` показывает превью группы (новая RPC `get_group_by_code`).
- Группы бывают **публичные** (находятся поиском, вступить может любой) и **приватные** (не видны в поиске, вступить можно только по ссылке-приглашению). Тип выбирается при создании, по умолчанию публичная; admin может сменить тип на экране «О группе» (4.7).
- Этап 5: реакции — 6 быстрых (👍 ❤️ 😂 😮 😢 🙏); личные сообщения — из списка участников и через поиск по @username (не по имени); звука нет; удалять сообщение может автор, в группе — ещё и admin.
- Бэклог этапа 7 «Полировка»: «Печатает…» (5.7, нужна миграция), удалить отладочную плашку `?debug=touch` и переключатели, вычитка kk/en носителем (спорные места в отчёте 4.8), вернуть анимацию меню на iOS в лёгком виде, назначить admin групп без админа (в т.ч. демо-группы из seed.sql), сохранение неотправленных сообщений при закрытии вкладки.
- Этап 6: только фото и голосовые (видео и обычные файлы — позже, если останется бюджет); голосовое до 1 минуты; фото сжимаются в браузере до 1600 px.
- Аватарки: фото профиля и групп с кадрированием (квадрат/круг), сжатие до 512 px; фото группы меняет admin на экране «О группе» (при создании группы — цвет и буквы). Логотип: `docs/brand/` хранит исходник, в приложении — PNG-иконки.
